# AI 판단기준 변경 이력 (프롬프트 재작성 시 반드시 유지할 결정들)

프롬프트를 다시 쓸 때 이 목록의 결정이 빠지면 과거에 실제 사례로 잡았던 오류가 되살아남.
각 항목은 "왜 그렇게 정했는지"까지 같이 적음. (커밋 해시는 git log 참고)

## 대원칙 (2026-09 재정립)
- 목적은 정확한 지급. 돈을 안 주려는 도구가 아님. 근거 없는 삭감과 근거 없는 인정은 같은 무게의 오류.
- AI는 규칙표 대조기가 아니라 판단 주체. 프롬프트는 "무엇을 보고, 어떤 순서로 생각하고, 어떤 형식으로 답할지"만 정하고 결론을 미리 정해주는 절대규칙은 두지 않음.
- 판단 순서: 손상 관찰 → 정비사 관점 복원 가능 여부 → 불가면 교환 / 가능하면 수리 수준(유형·판금 등급·도장 등급) → 복원은 되나 비용이 교환에 근접하면 협의 + 비용 비교 → 부수·중복·도장·시간 검토.
  - 이전 구조(도장막 상태로 1~3유형을 먼저 매기고 교환은 "3유형이라도 예외")가 도장 멀쩡한 꺾임(펜더 가장자리 크리스 + 램프 접합부 단차)을 2유형으로 내린 사례가 계기.
- 회사 수치(시간표·한도·허용목록)는 [참고자료]로 들어올 때만 적용. 프롬프트에 박지 않음.
- 건 전체 순서 (v4.1/adj3.1): ① 파손 검토 → 필요 메인·부수작업(명확한 범위) → ② 청구 대조 + 작업사진 검증(직접확인) → ③ 범위 밖 청구는 파손 형태·충격 방향으로 파손 가능성 추론(인정/협의/불인정, 모두 "추론" 표기) → ④ 내부 기준으로 시간·수량·도장 등급 대조(협의·과다) → ⑤ 직접확인/추론 구분 표기.
  - 계기: 펜더 교환 건에 휠하우스·사이드멤버·프론트필러 판금이 작업사진만으로 전부 인정으로 나옴. 작업사진은 "했다"의 증명이지 "필요했다"의 증명이 아님(뜯으면 다 주는 구조 금지). 휠하우스는 개연성 충분, 사이드멤버는 충격 방향상 애매, 필러 힌지부는 도어 단차 근거 없으면 협의.
  - 출력: judgment_basis("직접확인"|"추론") 필드, 화면 "추론" 배지 + 실험 표 "추론만" 필터, 복사 텍스트 [추론].

## 교환 vs 수리
- 교환 판정 3구간 (v3.4/adj2.5): 복원 곤란 근거 있으면 인정 / 완만한 함몰·긁힘에 교환이면 과다청구 / 사이는 협의필요 + cost_comparison(교환안 vs 수리안). 금액은 청구서 인쇄 금액과 청구서 단가 환산치만(AI 자체 산정 금지).
- 외판 교환은 손상 기준으로 결론 (v3.5/adj2.6): 손상·탈거 사진이 있으면 "신품 장착 사진 없음"으로 불인정 금지. reasoning 첫 문장은 "판금이 맞다 / 교환이 맞다".
- 범퍼(PP): 표면 균열 선은 소재 파단인 경우가 대부분 → 교환이 맞는 경우가 대부분. 이면 사진이 없다는 이유만으로 협의로 미루지 않음 (v3.7). 후미·전면추돌 범퍼는 표면이 가벼워도 사이드마운팅브라켓·체결탭·펜더 접합부 벌어짐을 확인 (adj2.1).
- 백도어 등 저가 패널은 교환안이 수리안과 비슷하거나 싼 경우가 많음 → 비용 비교에 반영 (v3.3).
- 경미손상 1~3유형은 적용대상 외판(앞뒤범퍼·후드·프런트펜더·도어·리어펜더·트렁크리드/백도어)에만. 그 외 부품은 정비 지식으로 직접 판단하고 damage_type "비대상(교환예외)".

## 시간 판단
- 판금·복원수리 시간만 과다 여부 판단. 탈착·도장공정·가열건조는 AOS 정시표 표준값이라 시간 자체는 판단하지 않음(작업유형의 정당성만) (v1.8).
- 작업유형이 정당화되지 않으면(수리로 충분한 손상에 교환 청구) 그 시간이 표준값이라도 "적정"이라 하지 않음 (v1.7).
- 판독 축(면적·프레스라인·꺾임·패임·이면 접근성·재질) → 소/중/대손상 등급 → 참고자료 시간표 → 없으면 숙련 판금공 시각으로 추정 (v3.0).

## 부수작업·중복
- 필수/선택 축 (adj2.6): 메인 작업에 정비 절차상 반드시 수반되는 작업은 사진 없어도 인정. "필요성은 있는데 사진이 없다"로 협의·불인정 금지. 선택 작업은 근거 없으면 협의.
- 교환·절단 패널에 체결된 소형 부속(에어익스트렉터그릴·몰딩·클립류·접착식 부품)은 메인 교환 인정 시 파손 사진 없어도 인정 (adj2.1, adj2.6).
- 탈착 중복은 "같은 부품 자체의 탈착"만 대상. 인접 부품 탈착은 정상 부수작업 (adj2.2, 106건 중 104건 조정 사례).
- O/H 포함 부속품 분할 청구, 동일 부품 탈착 1회, 동시탈착 한쪽 공임은 실제 기준.
- 사진에 작업 흔적이 있고 청구됐다는 사실만으로 인정 근거가 되지는 않음(손상·수리 범위와 무관한 작업).

## 근거 없는 청구
- 내판 판금은 양방향 (adj2.2): 변형·절단·용접·인장이 어느 사진에도 없으면 불인정, 보이면 범퍼 표면 인상과 무관하게 인정.
- 손해사정 기본값은 인정. 독립 판정 절반 이상이 불인정이면 기준 오적용으로 보고 재검토 (adj2.2).

## 단계별 차이
- 선견적(수리 전)은 작업 증빙(조색·이면·신품 장착 사진 등)을 요구하지 않음. 손상 대비 작업 종류·범위 타당성만 (v3.7).
- 손해사정(수리 후)은 새 손상 추론 금지, 청구-작업 대사 + 과잉수리 별도 확인 (adj1.1).
- 정비공정(견적 전)은 숨은 손상을 충격 강도에 비례해 추론, 램프류는 프레임에 보이면 무조건 항목화, 좌/우는 view_cue로 코드가 환산 (p2.6).

## 출력 형식
- "회사 기준 미제공 / AOS 확인 필요" 같은 군더더기 문구 금지, 정비 판단 결론까지만 (v3.8/adj2.7).
- 같은 작업이 두 곳(parts와 ancillary_work_check)에서 다른 판정 금지 (v3.10).
- 손해사정 종합의견 없음(항목별 판정이 결과). 선견적·정비공정은 종합의견 유지 (adj2.4).
- 교환도장·부품은 메인 판정에 연동(follows_parent). 메인 교환 불인정 시 교환도장은 "보수도장으로 변경"이지 과다청구가 아님 (adj2.1).
- photo_refs 필수, line_no는 견적서 NO(실험은 항목표 NO).

## 3008 측면 충돌 건에서 잡은 것 (v4.5/adj3.4)
- 같은 부위(group) 항목은 묶어서 본다: 도어 모듈판넬·트림 탈착이 인정된 부위에서 래치·윈도우모터·컨트롤모듈·배선·스피커를 개별 청구하면 O/H 분할 중복. "모듈판넬 분해에 수반"은 인정 사유가 아니라 중복 사유.
- 도장 등급과 탈착 범위 교차 확인: Lv2(패널 부착 외측만)인데 도어 탈착 + 내부 전체 분해면 서로 안 맞음. 이면 접근이 필요한 꺾임이면 분해 인정·Lv2 유지, 외측 손상뿐이면 분해가 과다.
- 한도 초과 0.1H 미만은 과다청구가 아니라 인정 + note (3.5H vs 3.45H 같은 0.05H 조정은 노이즈).

## K7 하이브리드 전후면 동시 충돌 건에서 잡은 것 (v4.6/adj3.5)
- 인접패널 블렌딩(보카시)은 인정하지 않음. 손상 없는 필러·도어에 "표면보수도장" 청구는 블렌딩이므로 불인정 (AI가 불인정한 게 맞았음). 컬러매칭(조색)은 별개.
- 재사용 가능 부품(혼·버저·VESS·센서·블로어·호스 등) 교환: 탈거품·신품 사진은 "했다"의 증거일 뿐. 파손 사진 없으면 파손 정도·장착 위치로 추론 — 충격 직접 전달 부위 + 주변 구조물 교환·변형이면 추론 인정, 가장자리·경미하면 협의 + 구품 파손 사진, 경로 밖이면 불인정. 사진 요구만 하지 말고 추론할 것.
- 판금 시간 큰 구조부(사이드멤버·휠하우스)는 그 면의 외판 밀림 깊이와 비례 대조. 전·후면 동시 손상은 면마다 따로. 반반이면 협의 + 계측자료.
- 정합성 경고는 촬영 시점 차이도 그대로 두고 담당자가 메모로 처리(3중 추돌 등).
- 한도 초과 0.1H "이하" 인정 + note.

## 출력 형식 정리 (v4.8/adj3.7/p3.2) — 판정 기준 변경 없음
- 출력 JSON 키를 축약형으로 보내고 서버에서 원래 키로 복원(wire-keys.ts). 화면·리포트는 원래 키만 봄.
- 손해사정 parent_line 필드 제거(어디서도 안 읽음). group·role·follows_parent는 유지.
- reasoning 상한: 인정은 한 문장, 그 외 두 문장 이내. adjustment_note·note·required_action 한 문장.
- 관리자 "AI 모델" 탭에 출력 상세도(상세/간략) 추가. 간략은 판정·항목 수·photo_refs·직접확인/추론 구분을 그대로 두고 문장만 구절로 압축. 실행 이력 태그에 -brief.
- 상세/간략 전체 검토 후 정리: 손해사정 "인정 + note" 모순은 adjustment_note 한도 메모 예외로 해소. 간략 모드 예외 — 판금·수리 항목은 판독 축 한 줄 유지, overall_opinion은 발신 형식 유지(항목당 한 문장), overall_summary 두 문장. 공통 블록 협의 용어를 도구별(협의대상/협의필요)로 병기. 정비공정은 판금 블록의 판독·등급(1~2단계)만 사용(견적서 대조 단계 제외).
